# CLAUDE.md

Pawn is a chess tournament management desktop app built with Tauri 2, React 19, and Rust. It supports Swiss, Round-robin, Knockout, and Team tournaments with FIDE-compliant pairing algorithms, offline-first SQLite storage, and multi-language support (EN/RU/UK).

## Architecture

### Frontend

```
src/
├── app/            # App entry, providers, routes, global styles
├── pages/          # Route-level components (new-tournament, settings, tournament-info, tournaments)
├── widgets/        # Composite UI blocks with extracted hooks for state management
│   ├── export-dialog/
│   ├── new-tournament-form/
│   ├── player-management/    # PlayerManagement + usePlayerManagement hook
│   ├── results-grid/         # ResultsGrid + useResultsGrid hook
│   ├── round-manager/        # RoundManager + useRoundManager hook + roundStatusUtils
│   ├── standings-table/
│   ├── tournament-list/
│   └── tournament-sidebar/
├── shared/         # Shared code (config, hooks, layouts, lib, types, ui)
├── dto/            # Auto-generated TypeScript bindings from Rust (bindings.ts)
├── locales/        # i18n translation files (en, ru, ua)
└── test/           # Test infrastructure (vitest + playwright)
```

Widget components follow a pattern of extracting business logic into custom hooks (e.g., `useRoundManager`, `usePlayerManagement`, `useResultsGrid`) to keep components focused on presentation.

### Backend (Rust/Tauri)

```
src-tauri/src/
├── command/    # Tauri command handlers (thin delegates to services)
├── service/    # Business logic layer (primary test target)
│   ├── swiss_pairing/    # FIDE Dutch system (split into color, team_avoidance, bye_and_float modules)
│   ├── pairing.rs        # Pairing orchestrator (Swiss + Round-robin dispatch)
│   ├── round.rs          # Round lifecycle and status transitions
│   ├── tournament.rs     # Tournament CRUD and status management
│   ├── tiebreak.rs       # Tiebreak calculation engine
│   ├── export.rs         # PDF/Excel/HTML/CSV export
│   └── ...               # player, team, settings, knockout, seeding, validation, etc.
├── domain/     # Data models (model.rs) and DTOs (dto.rs)
├── db/         # SQLite database access (SQLx) with migrations
├── common/     # Error types (PawnError, ErrorCode), macros, constants
├── state.rs    # Service container (Arc-wrapped service wiring)
└── templates/  # Tournament configuration templates
```

### Key Patterns

- **Service layer**: All business logic lives in `service/`. Commands are thin delegates.
- **Error codes**: `common/error.rs` defines `ErrorCode` enum for structured backend errors (e.g., `IncompleteGames`, `RoundInvalidTransition`). Frontend parses these via `parseBackendError()` in `shared/lib/errorUtils.ts`.
- **Notifications**: Use `useNotification()` from `shared/lib/notification` for toast messages. Contextual errors within widgets use inline `Alert` components.
- **Type generation**: `src/dto/bindings.ts` is auto-generated by `pnpm generate-bindings` — never edit manually.

## Coding Conventions

- No `any` types — set types at variable declaration
- No type casting (`as`) — prefer type annotations or generics
- Auto-generated types live in `src/dto/bindings.ts` — never edit manually
- Frontend uses MUI v7, react-hook-form, i18next, Biome (lint + format)
- Backend follows service pattern: command -> service -> db
- Widget state logic belongs in custom hooks (`useXxx`), not inline in components
- Shared components must not import from widgets/pages (FSD layer rule)

## Commands

### Development

```bash
pnpm tauri dev          # Full app with hot reload
pnpm dev                # Frontend only (localhost:1420)
cd src-tauri && cargo build  # Backend only
```

### Testing

```bash
# Frontend
pnpm test               # Unit tests (vitest, interactive)
pnpm test -- --run      # Unit tests (single run, CI)
pnpm test:e2e           # Playwright E2E

# Backend
cd src-tauri && cargo test                    # All tests
cd src-tauri && cargo test swiss_pairing      # Specific module
cd src-tauri && cargo test --test integration # Integration tests
```

### Building

```bash
pnpm build              # Frontend (tsc + vite)
pnpm tauri build        # Full desktop app with installers
```

### Code Quality

```bash
pnpm check              # Biome lint + format (single command)
pnpm check:fix          # Biome auto-fix lint + format
pnpm type-check         # TypeScript validation
pnpm quality:check      # Full quality gate (lint + format + types + locales + tests)
pnpm quality:fix        # Auto-fix what can be fixed
cd src-tauri && cargo fmt       # Rust format
cd src-tauri && cargo clippy    # Rust lint
```

### Database

```bash
pnpm db:migrate         # Run migrations
pnpm db:reset           # Reset database and re-migrate
```

### Locales

```bash
pnpm locales:check      # Check translation key consistency
pnpm locales:fix        # Auto-fix missing keys
```

### System Dependencies (Ubuntu/Debian)

sudo apt-get install -y libsqlite3-dev pkg-config libwebkit2gtk-4.1-dev \
  build-essential curl wget file libxdo-dev libssl-dev \

## Testing Strategy

- **Service tests**: All business logic tested in `src-tauri/src/service/` modules
- **Widget tests**: Widgets tested via `@testing-library/react` in `__tests__/` directories
- **Tauri limitation**: Command wrappers in `command/` cannot be unit tested (`tauri::State<T>` has private fields). These are thin delegates with zero logic.
